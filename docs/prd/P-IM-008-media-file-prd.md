# P-IM-008 文件与媒体 生产级蓝图

## 1. 背景

MallChat 已具备基础文件上传能力（`mallchat-file-service`），支持图片、文件、语音、视频四种媒体类型的上传校验和 COS 存储。聊天消息已定义 6 种类型（TEXT/IMAGE/FILE/VOICE/VIDEO/STICKER），并通过 `extra` JSON 字段携带媒体元数据。动态（Moment）已支持最多 9 张媒体附件。

但当前实现存在以下生产化缺口：

1. **权限边界不完整**：上传后文件 URL 为公开访问，缺少基于会话成员的访问控制。
2. **消息引用薄弱**：`replyMsgId` 已存在但回复消息的媒体预览未标准化。
3. **动态媒体校验不足**：动态发布时仅校验 URL 非空，未校验 URL 归属和媒体类型一致性。
4. **审计与合规缺失**：上传审计日志已有，但缺少敏感内容检测、重复文件去重和存储配额控制。
5. **端到端流程未闭环**：客户端上传 → 发消息 → 接收方展示的全链路缺少统一的异常处理和降级策略。

## 2. 目标

```gherkin
Given 用户已登录 MallChat
When 用户在私聊/群聊中发送图片、文件、语音或视频消息
Then 系统应完成上传校验、存储、消息投递和接收方实时展示
And 媒体文件应遵循访问权限控制
And 上传行为应有完整审计记录
```

### 2.1 SMART 目标

| 编号 | 目标 | 衡量标准 | 达成条件 |
|------|------|----------|----------|
| G1 | 文件上传安全校验覆盖所有媒体类型 | 每种类型的大小、格式、magic byte 校验均有对应测试 | P0 完成 |
| G2 | 媒体消息端到端投递可靠 | 发送方成功 → 接收方通过 WebSocket 收到完整媒体元数据 | P1 完成 |
| G3 | 动态媒体引用完整 | 动态发布、展示、删除时媒体数据一致 | P1 完成 |
| G4 | 文件访问权限可控 | 非会话成员无法访问私聊媒体文件 | P2 完成 |
| G5 | 上传审计可追溯 | 每次上传（成功/失败）均有审计记录，可按用户和时间查询 | P0 完成 |

## 3. 非目标

- 不实现文件在线预览（如 PDF 渲染、视频转码播放）。
- 不实现文件版本管理或历史版本回溯。
- 不实现跨服务文件同步或文件分享链接。
- 不实现客户端本地缓存策略或离线文件访问。
- 不实现图片编辑（裁剪、滤镜）能力。
- 不替换 COS 为其他存储方案。

## 4. 核心内容

### 4.1 核心用户故事

| 编号 | 角色 | 故事 | 验收条件 |
|------|------|------|----------|
| US-01 | 发送方 | 我想在聊天中发送图片，让对方看到图片预览 | 图片消息在接收方聊天窗口正确展示缩略图和大图 |
| US-02 | 发送方 | 我想发送文件（PDF/Word/Excel），让对方下载 | 文件消息展示文件名、大小、类型图标，点击可下载 |
| US-03 | 发送方 | 我想发送语音消息，让对方播放 | 语音消息展示时长和播放控件 |
| US-04 | 发送方 | 我想发送视频消息，让对方播放 | 视频消息展示封面、时长和播放控件 |
| US-05 | 发送方 | 我想回复一条图片消息，对方能看到我在回复什么 | 回复消息展示原消息的媒体预览 |
| US-06 | 动态发布者 | 我想在动态中附加图片，让好友看到 | 动态展示最多 9 张图片，支持排序 |
| US-07 | 管理员 | 我想查看某用户的上传记录，用于合规审计 | 可按用户 ID 和时间范围查询上传审计日志 |
| US-08 | 接收方 | 我不想看到非法或恶意文件 | 上传时系统拒绝非法格式、伪装文件和超大文件 |

### 4.2 数据与权限边界

| 资源 | 写权限 | 读权限 | 删除权限 |
|------|--------|--------|----------|
| 文件上传 | 已登录用户 | 上传者本人 | 不支持（COS 不删除） |
| 聊天媒体消息 | 会话成员 | 会话成员 | 消息发送者（撤回） |
| 动态媒体 | 动态发布者 | 好友/可见范围 | 动态发布者 |
| 上传审计日志 | 系统自动 | 管理员 | 不支持 |

### 4.3 状态模型

```
文件上传流程：
[选择文件] → [客户端校验] → [调用上传接口] → [服务端校验] → [COS 存储] → [返回 URL]
                                                          ↓
                                                    [校验失败] → [返回错误]

媒体消息流程：
[上传成功] → [构建 extra JSON] → [发送消息] → [消息入库] → [WebSocket 推送] → [接收方展示]

动态媒体流程：
[上传成功] → [构建 mediaList] → [发布动态] → [媒体入库] → [动态展示]
```

### 4.4 产品边界

1. **上传与消息解耦**：客户端先调用文件服务上传，获得 URL 后再通过消息接口发送。聊天服务不直接调用文件服务。
2. **extra 字段契约**：每种消息类型的 `extra` JSON 结构已由 `ChatMessageHelper` 定义，前端必须严格遵循。
3. **动态媒体限制**：单条动态最多 9 个媒体，URL 最大 1024 字符。
4. **存储后端固定**：当前仅支持腾讯云 COS，不抽象多存储适配层。

## 7. 风险与边界

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| COS 公开 URL 无法实现访问控制 | 中 | P2 阶段评估签名 URL 或代理方案 |
| 大文件上传超时 | 中 | 已配置 100MB 限制，需监控实际使用 |
| magic byte 校验绕过 | 低 | 已有多层校验，持续补充边界用例 |
| 动态媒体删除后 COS 残留 | 低 | 当前不主动删除 COS 对象，后续可加异步清理 |
