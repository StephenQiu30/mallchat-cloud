# 群聊管理 PRD

## 1. 背景

后端已有群聊创建、邀请好友、群详情、成员列表、退群、解散和拒绝公开加入的 MVP 能力。`chat_group_info` 表已经存储群名称、头像、公告和创建者。

当前缺口在于 QQ-like 群聊的治理能力：群公告编辑、入群申请/审核、管理员权限、成员禁言、踢人、群资料变更通知和群通知中心尚未完整形成。

## 2. 产品目标

1. MVP 保持受控群聊入口：创建群、邀请好友、成员列表、退出/解散。
2. P1 支持群资料和群公告编辑、成员角色管理、踢人和入群审核。
3. P2 支持禁言、群昵称、群活跃数据和管理后台治理。

```gherkin
Given 用户是群主
When 用户更新群公告
Then 群成员应能看到新的公告
And 系统应推送群资料变更事件或通知
```

## 3. 非目标

- 不在首版实现开放搜索入群和超大群。
- 不实现复杂等级、头衔、群空间和群应用。
- 不绕过好友关系直接批量拉人入群。

## 4. 核心用户故事

### 4.1 群主

作为群主，我希望创建群聊、邀请好友、更新群资料并管理成员。

验收标准：
- 创建群聊时创建者成为群主。
- 邀请成员必须是邀请人的好友，且去重。
- 群主可以解散群聊，解散后所有成员会话移除。

### 4.2 群成员

作为群成员，我希望查看群资料、群公告和成员列表，并能主动退群。

验收标准：
- 只有群成员可以查看群详情和成员列表。
- 普通成员可以退群，群主不能直接退群。
- 退群后不能继续拉取历史消息或发送消息。

### 4.3 管理员

作为未来群管理员，我希望具备有限治理权限。

验收标准：
- P1 区分群主、管理员、普通成员。
- 管理员权限范围必须小于群主。
- 角色变化需要记录并推送给相关成员。

## 5. 数据与权限边界

- `chat_room` 记录房间基础属性。
- `chat_group_info` 记录群名、头像、公告。
- `chat_room_member` 记录成员、角色和最后已读边界。
- 群成员缓存只能作为权限校验加速层，数据库仍是事实来源。

## 6. 首版验收门禁

- 群创建、邀请、详情、成员列表、退群、解散均有测试覆盖。
- 新增群公告或角色管理时必须覆盖权限边界测试。
- 群资料变更应有会话或通知更新策略。

## 7. 风险与边界

- 公开入群与邀请入群的权限差异大，应单独做 OpenSpec。
- 群成员缓存冷启动需要与实时推送可靠性 PRD 协同处理。

## 8. 待确认问题

- P1 是否需要群管理员？
- 入群审核是否先支持“群主审批”，还是“管理员也可审批”？
- 群公告变更是否要生成系统消息写入聊天记录？
