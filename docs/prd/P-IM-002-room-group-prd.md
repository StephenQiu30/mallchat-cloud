# P-IM-002 房间与群聊 PRD

## 1. 背景

MallChat IM 已实现基础的房间创建、私聊房间、成员管理、邀请、踢人、退出、解散和加入审批能力。但现有实现偏向功能原型，缺少群主转让、禁言、细粒度权限框架、房间设置、@提及和消息置顶等生产级功能。

本 PRD 旨在梳理现有能力、明确补齐项，为后续 TDD 驱动的实现提供清晰的产品边界和验收标准。

## 2. 目标

```gherkin
Given 用户已登录 MallChat
When 用户执行房间或群聊相关操作
Then 系统应提供完整的房间生命周期管理和群聊协作能力
And 所有操作应遵循权限控制和状态约束
And 关键行为应有可验证的验收标准
```

核心目标：

1. 补齐私聊房间和群聊房间的生产级能力缺口。
2. 建立清晰的成员权限体系，支持群主、管理员和普通成员三级角色。
3. 确保所有房间操作有明确的状态流转和边界约束。
4. 为后续 TDD 实现提供可执行的验收门禁。

## 3. 非目标

- 不涉及消息存储、消息推送和消息同步的具体实现（由其他 Epic 覆盖）。
- 不涉及音视频通话能力。
- 不涉及跨平台客户端 UI 实现细节。
- 不涉及用户注册、登录和认证流程（假设已存在）。

## 4. 核心用户故事

### 4.1 私聊房间

| ID | 故事 | 验收标准 |
|----|------|----------|
| US-R01 | 用户 A 向用户 B 发起私聊，系统自动创建私聊房间 | 两个用户之间只能存在一个私聊房间；重复发起返回已有房间 |
| US-R02 | 用户查看私聊房间列表 | 列表按最后消息时间倒序；显示对方头像、昵称和最后一条消息预览 |
| US-R03 | 用户退出私聊房间 | 退出后房间对退出方不可见；对方仍保留房间 |

### 4.2 群聊创建与管理

| ID | 故事 | 验收标准 |
|----|------|----------|
| US-G01 | 用户创建群聊并指定初始成员 | 创建者自动成为群主；初始成员自动加入；群聊有唯一房间 ID |
| US-G02 | 群主或管理员邀请新成员 | 被邀请人收到邀请通知；可接受或拒绝 |
| US-G03 | 群主或管理员踢出成员 | 被踢成员移出群聊；被踢成员收到通知 |
| US-G04 | 成员主动退出群聊 | 退出后不再接收群消息；群主退出需先转让群主 |
| US-G05 | 群主解散群聊 | 所有成员被移除；房间标记为已解散；不可恢复 |

### 4.3 邀请与审批

| ID | 故事 | 验收标准 |
|----|------|----------|
| US-I01 | 邀请制群聊：新成员需审批加入 | 管理员收到审批请求；批准后成员加入；拒绝后成员不加入 |
| US-I02 | 开放群聊：新成员可直接加入 | 无需审批；加入后立即可见群消息 |

### 4.4 权限体系

| ID | 故事 | 验收标准 |
|----|------|----------|
| US-P01 | 群主转让群主身份给其他成员 | 新群主获得全部群主权限；原群主降为普通成员 |
| US-P02 | 群主设置管理员 | 管理员可邀请/踢出普通成员；不可踢出其他管理员或群主 |
| US-P03 | 群主撤销管理员 | 被撤销者降为普通成员 |

### 4.5 高级功能

| ID | 故事 | 验收标准 |
|----|------|----------|
| US-A01 | 群主或管理员禁言成员 | 被禁言成员不可发送消息；可设置禁言时长 |
| US-A02 | 群主或管理员解除禁言 | 被解除成员恢复发送消息能力 |
| US-A03 | 群主修改群聊设置（名称、头像、公告） | 修改后所有成员可见更新 |
| US-A04 | 成员在群聊中 @提及其他成员 | 被 @的成员收到特别通知 |
| US-A05 | 群主或管理员置顶消息 | 置顶消息在群聊顶部显示 |

## 5. 用户体验原则

1. **状态可见**：用户应能清晰看到房间状态（正常、已解散）和成员状态（正常、已禁言）。
2. **操作反馈**：所有操作应有即时反馈（成功提示、错误提示）。
3. **权限提示**：无权限执行操作时，应给出明确提示而非静默失败。
4. **边界保护**：群主退出前必须转让群主；解散操作需二次确认。

## 6. 数据与权限边界

### 6.1 数据收集

- 房间基本信息：名称、头像、类型（私聊/群聊）、创建时间。
- 成员关系：用户 ID、房间 ID、角色（群主/管理员/成员）、加入时间。
- 邀请记录：邀请人、被邀请人、房间 ID、状态（待审批/已接受/已拒绝）。
- 禁言记录：用户 ID、房间 ID、禁言开始时间、禁言结束时间。

### 6.2 权限矩阵

| 操作 | 群主 | 管理员 | 普通成员 |
|------|------|--------|----------|
| 修改群信息 | ✅ | ❌ | ❌ |
| 邀请成员 | ✅ | ✅ | ❌ |
| 踢出成员 | ✅ | ✅（仅普通成员） | ❌ |
| 审批加入 | ✅ | ✅ | ❌ |
| 转让群主 | ✅ | ❌ | ❌ |
| 设置管理员 | ✅ | ❌ | ❌ |
| 禁言成员 | ✅ | ✅（仅普通成员） | ❌ |
| 置顶消息 | ✅ | ✅ | ❌ |
| 解散群聊 | ✅ | ❌ | ❌ |
| 退出群聊 | 需先转让 | ✅ | ✅ |

## 7. 状态模型

### 7.1 房间状态

```text
[正常] --解散--> [已解散]
```

- 正常：房间可正常使用。
- 已解散：房间不可用，成员不可发送消息。

### 7.2 成员状态

```text
[正常] --禁言--> [已禁言] --解除--> [正常]
[正常] --退出/被踢--> [已离开]
```

### 7.3 邀请状态

```text
[待审批] --批准--> [已接受]
[待审批] --拒绝--> [已拒绝]
```

## 8. 技术方案

沿用 MallChat 当前架构风格：

- **Controller**：RESTful API 入口，参数校验和响应封装。
- **Service**：业务逻辑接口定义。
- **ServiceImpl**：业务逻辑实现。
- **Mapper**：数据访问层。
- **Entity**：数据库实体映射。
- **Convert**：Entity ↔ DTO/VO 转换。
- **DTO/VO**：请求参数和响应视图对象。

关键表设计参考：

- `room`：房间主表。
- `room_member`：房间成员关系表。
- `room_invitation`：邀请记录表。
- `room_mute`：禁言记录表。

## 9. 首版验收门禁

1. 所有 P0 功能项有对应的单元测试和集成测试。
2. 权限矩阵中每个角色-操作组合有正向和反向测试用例。
3. 状态流转有边界条件测试（如群主退出未转让、重复邀请等）。
4. API 接口有契约测试覆盖。
5. 关键用户故事有端到端验收脚本。

## 10. 待确认问题
