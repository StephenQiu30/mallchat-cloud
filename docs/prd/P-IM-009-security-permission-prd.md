# P-IM-009 安全权限 PRD

## 1. 背景

MallChat 当前认证体系基于 Sa-Token JWT + 简单三角色 RBAC（user/admin/ban），群聊侧有 Owner/Admin/Member 角色但权限检查分散在各 ServiceImpl 中。存在以下问题：

1. **好友权限缺失**：无好友申请验证、被拉黑用户仍可发送消息、无好友分组权限控制。
2. **群成员权限粗糙**：群管理员无法精细控制邀请、踢人、禁言、公告等操作；群主转让无流程。
3. **动态可见性缺失**：朋友圈动态无可见范围控制（公开/好友/私密），被拉黑用户仍可看到动态。
4. **撤回权限不完整**：消息撤回无时间窗口限制，非管理员可撤回他人消息。
5. **举报机制不完善**：举报对象类型有限，举报后无管理员审核流程和处置动作。
6. **频控缺失**：无限速保护，恶意用户可高频发送消息、添加好友、发举报。
7. **审计缺失**：关键操作无审计日志，无法追溯权限变更、敏感操作。

## 2. 目标

```gherkin
Given 用户已登录 MallChat
When 用户执行涉及权限的操作（添加好友、发消息、查看动态、撤回消息、举报）
Then 系统应根据权限模型进行鉴权，拒绝无权操作并返回明确错误码
And 关键操作应记录审计日志
```

### 2.1 具体目标

| 编号 | 目标 | 验证方式 |
| --- | --- | --- |
| G1 | 好友申请、通过、拉黑流程完整闭环 | 好友申请 → 通过 → 成为好友；拉黑后无法发消息 |
| G2 | 群成员权限按角色分级，群主可转让 | 不同角色执行操作时返回正确权限校验结果 |
| G3 | 动态可见性支持公开/好友/私密三种模式 | 不同可见性下非授权用户无法查看 |
| G4 | 撤回权限限制在 2 分钟内且仅限自己消息 | 超时或非本人消息撤回返回错误 |
| G5 | 举报覆盖消息/用户/动态，支持管理员审核 | 举报创建 → 审核 → 处置完整流程 |
| G6 | 消息/好友/举报操作有频控保护 | 超频请求返回 429 错误 |
| G7 | 权限变更和敏感操作有审计日志 | 查询审计日志可追溯操作人、时间、动作 |

## 3. 非目标

1. 不实现细粒度 API 级别权限表（当前 SaCheckRole 够用）。
2. 不实现端到端加密（超出当前 MVP 范围）。
3. 不实现多租户权限隔离。
4. 不实现动态工作流审批（举报审核使用简单通过/拒绝）。
5. 不实现 IP 黑名单或 WAF 层防护（由基础设施层处理）。

## 4. 核心用户故事

### 4.1 好友权限

| ID | 故事 | 验收标准 |
| --- | --- | --- |
| US-F1 | 作为用户，我想发送好友申请，附带验证消息 | 申请创建成功，对方收到通知 |
| US-F2 | 作为用户，我想通过/拒绝好友申请 | 通过后双方成为好友；拒绝后申请状态更新 |
| US-F3 | 作为用户，我想拉黑某人 | 拉黑后对方无法发消息、查看动态 |
| US-F4 | 作为用户，我想解除拉黑 | 解除后恢复正常交互 |
| US-F5 | 作为用户，被拉黑后发消息应被拒绝 | 返回明确错误码 BLOCKED_BY_TARGET |

### 4.2 群成员权限

| ID | 故事 | 验收标准 |
| --- | --- | --- |
| US-G1 | 作为群主，我想设置/撤销管理员 | 仅群主可操作，撤销后降为普通成员 |
| US-G2 | 作为群管理员，我想踢出成员 | 管理员可踢普通成员，不可踢其他管理员 |
| US-G3 | 作为群主/管理员，我想禁言成员 | 禁言后该成员无法发送消息 |
| US-G4 | 作为群主，我想转让群主 | 转让后原群主降为管理员，新群主升级 |
| US-G5 | 作为群主，我想设置群为仅管理员可邀请 | 设置后普通成员邀请需管理员审批 |

### 4.3 动态可见性

| ID | 故事 | 验收标准 |
| --- | --- | --- |
| US-M1 | 作为用户，我想发布动态时选择可见范围 | 支持公开/好友/私密三种模式 |
| US-M2 | 作为用户的好友，我想查看好友的"好友可见"动态 | 好友可见动态对好友可见，对非好友不可见 |
| US-M3 | 作为被拉黑用户，我想查看对方动态 | 返回空或无权限错误 |

### 4.4 撤回权限

| ID | 故事 | 验收标准 |
| --- | --- | --- |
| US-R1 | 作为发送者，我想在 2 分钟内撤回自己的消息 | 撤回成功，消息状态变为 recalled |
| US-R2 | 作为发送者，我想撤回超过 2 分钟的消息 | 返回 RECALL_TIMEOUT 错误 |
| US-R3 | 作为群管理员，我想撤回群内任意消息 | 管理员/群主可撤回任何消息 |
| US-R4 | 作为普通成员，我想撤回他人消息 | 返回 NO_PERMISSION 错误 |

### 4.5 举报

| ID | 故事 | 验收标准 |
| --- | --- | --- |
| US-RP1 | 作为用户，我想举报消息/用户/动态 | 举报创建成功，管理员收到通知 |
| US-RP2 | 作为管理员，我想审核举报 | 可通过/拒绝举报，处置动作生效 |
| US-RP3 | 作为管理员，我想查看举报列表 | 支持按状态、类型筛选 |

### 4.6 频控

| ID | 故事 | 验收标准 |
| --- | --- | --- |
| US-FR1 | 系统应对消息发送限速 | 超过 30 条/分钟返回 429 |
| US-FR2 | 系统应对好友申请限速 | 超过 20 条/小时返回 429 |
| US-FR3 | 系统应对举报提交限速 | 超过 10 条/小时返回 429 |

### 4.7 审计

| ID | 故事 | 验收标准 |
| --- | --- | --- |
| US-A1 | 作为管理员，我想查看权限变更日志 | 记录包含操作人、时间、动作、目标 |
| US-A2 | 系统应自动记录敏感操作 | 踢人、禁言、转让群主、封禁用户等操作有日志 |

## 5. 用户体验原则

1. **明确反馈**：权限拒绝时返回具体错误码和可读提示，不返回通用 403。
2. **最小惊讶**：默认行为符合用户预期（如好友默认可看动态）。
3. **渐进披露**：高级权限设置在二级菜单，不干扰核心聊天体验。
4. **一致性**：所有权限校验使用统一错误码体系。

## 6. 数据与权限边界

1. **默认收集**：操作人 ID、操作时间、操作类型、目标对象。
2. **默认不收集**：操作原因（举报除外）、IP 地址（审计日志可选记录）。
3. **存储**：审计日志保留 90 天，到期自动清理。
4. **删除**：用户注销时，其举报记录保留（脱敏），审计日志保留。

## 7. 状态模型

### 7.1 好友申请状态

```
PENDING → APPROVED
PENDING → IGNORED
```

### 7.2 举报状态

```
PENDING → RESOLVED (通过，执行处置)
PENDING → REJECTED (拒绝)
```

### 7.3 消息状态

```
NORMAL → RECALLED (撤回)
NORMAL → DELETED (删除)
```

## 8. 技术方案（产品边界）

1. **认证层**：复用现有 Sa-Token + Gateway 认证，不变更。
2. **权限层**：在 ServiceImpl 中增加权限校验方法，复用现有 `SecurityUtils.getLoginUserId()`。
3. **频控层**：在 Gateway 增加 Redis 滑动窗口限流 filter。
4. **审计层**：在 `mallchat-log-service` 增加审计日志模块。
5. **数据层**：新增 `user_audit_log` 表、`chat_report` 表已有（需扩展字段）。

## 9. 首版验收门禁

- [ ] 好友申请 → 通过 → 拉黑 → 解拉黑完整流程可跑通。
- [ ] 群主转让、管理员踢人、禁言功能正常。
- [ ] 动态可见性三种模式下，非授权用户无法查看。
- [ ] 撤回权限校验正确（2 分钟窗口、仅限自己或管理员）。
- [ ] 举报创建 → 审核 → 处置流程完整。
- [ ] 消息、好友、举报频控生效（超频返回 429）。
- [ ] 审计日志可查询，覆盖关键操作。
- [ ] 所有新增功能有对应单元测试。

## 10. 待确认问题

1. 群主转让后是否允许撤回？（建议：不允许，已生效）
2. 被禁言用户是否可以退出群聊？（建议：可以，退出不受禁言影响）
3. 举报审核是否需要多级审批？（建议：MVP 单级审批）
4. 审计日志是否需要支持导出？（建议：后续版本）
5. 频控阈值是否需要可配置？（建议：MVP 硬编码，后续改配置）
