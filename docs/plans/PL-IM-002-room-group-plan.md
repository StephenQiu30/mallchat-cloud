# P-IM-002 房间与群聊实现计划

## 1. 背景

本计划基于 `docs/prd/P-IM-002-room-group-prd.md`，将房间与群聊功能拆解为 P0、P1、P2 三个阶段，按依赖关系和优先级排列，确保每个阶段可独立交付和验证。

## 2. 目标

1. 将 PRD 中的功能项拆解为可执行的子任务。
2. 按 P0（核心基础）→ P1（管理与权限）→ P2（高级体验）的顺序排列。
3. 每个子任务有明确的验收标准和 TDD 要求。
4. 为每个阶段创建对应的 Linear 子 Issue。

## 3. 非目标

- 不包含具体的技术设计细节（由 design 文档覆盖）。
- 不包含测试用例的具体实现（由 TDD 过程产出）。

## 4. 阶段拆解

### 4.1 P0：核心房间与私聊基础能力补齐

**目标**：确保房间和私聊的核心生命周期完整可用。

| 任务 ID | 任务 | 描述 | 验收标准 | 依赖 |
|---------|------|------|----------|------|
| P0-01 | 私聊房间去重 | 确保两个用户之间只存在一个私聊房间 | 重复创建返回已有房间 ID | 无 |
| P0-02 | 私聊房间列表 | 用户查看私聊房间列表，按最后消息时间倒序 | 列表正确排序；显示对方信息和最后消息预览 | P0-01 |
| P0-03 | 群聊创建 | 用户创建群聊并指定初始成员 | 创建者为群主；初始成员自动加入；返回房间 ID | 无 |
| P0-04 | 成员退出 | 成员主动退出群聊 | 退出后不再接收群消息；群主退出需先转让 | P0-03 |
| P0-05 | 群聊解散 | 群主解散群聊 | 所有成员移除；房间标记已解散 | P0-03 |
| P0-06 | 邀请加入 | 群主或管理员邀请新成员 | 被邀请人收到通知；可接受或拒绝 | P0-03 |
| P0-07 | 踢出成员 | 群主或管理员踢出成员 | 被踢成员移出群聊并收到通知 | P0-03 |
| P0-08 | 加入审批 | 邀请制群聊的加入审批流程 | 管理员可批准或拒绝；状态正确流转 | P0-06 |

**交付物**：

- 私聊房间去重和列表 API。
- 群聊创建、退出、解散 API。
- 邀请、踢人、审批 API。
- 对应的单元测试和集成测试。

### 4.2 P1：群聊管理与权限体系完善

**目标**：建立三级权限体系，支持群主转让和管理员设置。

| 任务 ID | 任务 | 描述 | 验收标准 | 依赖 |
|---------|------|------|----------|------|
| P1-01 | 群主转让 | 群主将群主身份转让给其他成员 | 新群主获得全部权限；原群主降为普通成员 | P0-03 |
| P1-02 | 设置管理员 | 群主设置普通成员为管理员 | 被设置者获得管理员权限 | P0-03, P1-01 |
| P1-03 | 撤销管理员 | 群主撤销管理员身份 | 被撤销者降为普通成员 | P1-02 |
| P1-04 | 权限校验 | 所有操作的权限校验逻辑 | 权限矩阵中每个角色-操作组合有正向和反向测试 | P1-01, P1-02, P1-03 |
| P1-05 | 管理员邀请限制 | 管理员只能邀请和踢出普通成员 | 管理员不可踢出其他管理员或群主 | P0-06, P0-07, P1-02 |

**交付物**：

- 群主转让 API。
- 管理员设置/撤销 API。
- 权限校验中间件或注解。
- 权限矩阵全覆盖测试。

### 4.3 P2：高级功能与体验优化

**目标**：补齐禁言、房间设置、@提及和消息置顶等增强功能。

| 任务 ID | 任务 | 描述 | 验收标准 | 依赖 |
|---------|------|------|----------|------|
| P2-01 | 成员禁言 | 群主或管理员禁言成员 | 被禁言成员不可发送消息；可设置禁言时长 | P1-04 |
| P2-02 | 解除禁言 | 群主或管理员解除禁言 | 被解除成员恢复发送消息能力 | P2-01 |
| P2-03 | 群聊设置修改 | 群主修改群名称、头像、公告 | 修改后所有成员可见更新 | P0-03 |
| P2-04 | @提及 | 成员在群聊中 @其他成员 | 被 @的成员收到特别通知 | P0-03 |
| P2-05 | 消息置顶 | 群主或管理员置顶消息 | 置顶消息在群聊顶部显示 | P0-03 |

**交付物**：

- 禁言/解除禁言 API。
- 群聊设置修改 API。
- @提及和消息置顶 API。
- 对应的单元测试和集成测试。

## 5. 依赖关系图

```
P0-01 ──→ P0-02
P0-03 ──→ P0-04, P0-05, P0-06, P0-07
P0-06 ──→ P0-08
P0-03 ──→ P1-01 ──→ P1-02 ──→ P1-03
P1-02, P1-03 ──→ P1-04
P0-06, P0-07, P1-02 ──→ P1-05
P1-04 ──→ P2-01 ──→ P2-02
P0-03 ──→ P2-03, P2-04, P2-05
```

## 6. 风险与边界

1. **权限体系复杂度**：三级权限体系可能引入较多边界条件，需通过 TDD 严格覆盖。
2. **群主转让原子性**：转让操作需保证原子性，避免出现无群主状态。
3. **禁言与消息发送的耦合**：禁言逻辑需与消息发送流程解耦，避免性能影响。
4. **并发操作**：多人同时邀请、踢人等操作需处理并发冲突。
